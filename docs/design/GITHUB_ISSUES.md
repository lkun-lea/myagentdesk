# GitHub Issue 只读关联

[#9](https://github.com/lkun-lea/myagentdesk/issues/9) 的试点从项目的「Issues」页开始。项目管理员连接一个公开 GitHub 仓库，成员按编号读取 Issue。详情显示来源状态、关闭原因、读取时间和需求阶段，可以打开 GitHub 原文。完整看板、跨仓分页、文本搜索、GitHub Projects 分列和私有仓库连接在 #9 后续切片验收。

管理员可将已查到的 Issue 关联到已有需求，或填写内部标题、说明和验收条件后创建需求。确认后可打开该需求，需求页可回到对应 Issue。Issue 的标题、正文和状态实时读取。内部需求只保存人确认的内容，关联以仓库稳定 ID 和编号去重。同一来源的并发请求返回已有需求，关联不会被覆盖。更换或断开仓库后，原关联保留供重新连接时追溯。

所有上游请求使用固定 GitHub API 主机和 GET。服务按项目成员身份、当前连接修订和 GitHub 公开可见性核验。若配置服务端读取凭据，获取 Issue 前后都核对仓库仍公开可见。远端标为私有、仓库断开、成员被移除或请求失败时，详情不返回旧数据。页面在刷新、重新聚焦及网络恢复时清除上次读取结果并重新核验。来源状态更新只影响当次读取，内部需求修订、阶段和验收继续以项目记录为准。

| 试点验收 | 操作与结果 |
| --- | --- |
| 读取真实来源 | 通过产品 API 连接公开仓库，读取一个真实 Issue，核对仓库、编号、状态、原文与读取时间。 |
| 创建及关联 | 项目管理员确认创建，或选择已有需求。并发提交和重试只得到一个关联，普通成员不能修改。需求与来源可双向跳转。 |
| 状态独立 | 用受控 GitHub 响应变更开放状态及关闭原因，确认原内部需求版本和阶段不变。 |
| 断开及撤权 | 测试项目移除成员、连接更换、仓库变为私有、限流和断网。敏感内容不从旧缓存补回。 |
