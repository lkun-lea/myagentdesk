# #14 tebb 桌面领取与恢复

MyAgentDesk 持有账号、派发、设备、候选和完成通知。tebb 持有本机设备凭据、目录确认、启动意图、终端运行和待回传记录。第一阶段沿用 #11 的固定提交、补丁和命令证据格式。

1. 在工作台需求群为每台桌面生成独立的一次性配对信息。从 tebb 的「连接与网络」粘贴并激活。首次激活绑定本机生成的凭据，原设备响应丢失时凭同一凭据重试。第二台设备需要自己的配对信息。
2. 工作台在当前阶段向获指派成员派发。已配对设备读取同一队列，工作台按派发原子记录唯一领取设备。tebb 在用户核对需求、仓库、候选 SHA，确认本机克隆和命令清单后才请求领取。发给桌面的派发引用不包含执行命令。
3. tebb 先保存授权和启动意图，再调用已有终端沙箱。每个用例绑定稳定请求编号。启动响应丢失或者进程重启时，以原编号查终端记录；结果无法确认时保存「待核对」，停止该派发的自动启动。
4. tebb 在发送前保存最终回执。断网或确认响应丢失时，重试同一个派发和完全相同的回执。工作台在一个事务内写入回执、候选关联和通知。重复回执返回原确认，异内容报冲突。「待核对」以单独的事件通知负责人。
5. 工作台账号可撤销配对；设备领取和回传均重新核对当前账号岗位。阶段、仓库连接或计划变化后，旧回执可入历史，当前阶段以匹配的候选推进。

## 验收标准

实际运行见 [桌面领取与恢复验收](../evals/tebb-desktop-delivery-20261119.md)。

- 同一条真实 #10 分发给两台配对设备。先核对零授权时无命令启动，两台确认后原子争抢只允许一台执行。
- 丢弃领取响应后重试，再在原终端已经启动、桌面尚未记录响应时中断。新桌面实例从磁盘读取原终端运行及原始证据，启动计数保持一次。
- 沙箱完成后切断工作台连接。桌面重新连接后发送本地回执，再丢弃首次入档后的确认响应。补传只留一个完成通知和一个候选。
- 启动意图已保存但本机找不到原终端记录时，重启后显示「待核对」。工作台给出待核对事件并维持原阶段，重试不会重新启动。
- 原申请账号以外的设备和撤销设备均不能领取或回传，刚配对代码只能由第一个设备凭据激活。

本切片使用固定候选和单文件回传。自动编码、tebb 自发任务提交与产物分片续传继续由 #14 后续阶段覆盖。
