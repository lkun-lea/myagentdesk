# #16 Demo 需求页与公共页头验收

2026-11-19 用 Node.js 22 构建生产包，在 Edge 打开 `/?demo=1`。需求样例来自 [MyAgentDesk #18](https://github.com/lkun-lea/myagentdesk/issues/18)，登录验证记录来自 [PR #17](https://github.com/lkun-lea/myagentdesk/pull/17)。

| 验收项 | 操作与结果 |
| --- | --- |
| 公共页头 | 从时间线依次切到规格、需求、Issues、构建与发布，再回到时间线和需求。项目名称位置一致，左侧项目入口始终可见。当前文字页签为透明背景和 2 px 蓝色底线，需求列表标题左侧留白为 16 px。 |
| 紧凑列表 | Semi Design 表格显示 8 条 Issue 摘录，使用内容区全宽。桌面数据行高不超过 40 px。#18 同时显示 GitHub 的「开放」和演示流程的「验收阻塞」。 |
| 流程与证据 | 键盘打开 #18 时先显示全宽流程。选择 Gmail 节点后，右栏显示「未分配」、阻塞原因、Brevo 投递回执、Gmail 实收待验证和预览取码记录。前两项链接到 #18，预览取码链接到 PR #17。 |
| 节点切换与退出 | 从列表的阻塞按钮可直接进入 Gmail 节点。切换到 QQ 节点时证据随节点更新。关闭右栏后焦点回到节点，再按 Esc 返回列表原入口。 |
| 宽度与主题 | 桌面截图使用 1120 px 视口。另检查 320、390、768、900、1024 px 下的表格和流程布局，页面无横向溢出。在 320 和 390 px 时，阶段详情排列在流程下方。切换深色后核对画布和阻塞标签。 |
| 原有入口 | 从时间线打开 #11 的依赖详情后用 Esc 恢复焦点。从 Issues 打开 #18 的验收标准。从「试点演示」进入 tebb #313 的试点需求，经规格页返回同一需求。 |
