# #9 首版单条 GitHub Issue 关联验收

浏览器使用同源应用、隔离 PostgreSQL 和测试身份，GitHub 来源来自真实公开仓库。匿名查询先遇到上游限流，页面显示读取限额错误。随后在隔离进程配置现有 GitHub CLI 读取凭据，通过产品入口连接 `lkun-lea/myagentdesk`、打开真实 #9、确认一条试点需求、从 Issue 跳转需求并回到同一来源。核对原文链接、公开状态和最近读取时间。断开仓库后，浏览器清掉来源详情。桌面、深色和 390px 窗口通过，无横向溢出。没有编辑真实 Issue，试点需求只存在于隔离项目。

| 用例 | 验收结果 |
| --- | --- |
| 并发创建和确认 | 三次并发提交只产生一条内部需求、来源关联和时间线事件。普通成员提交被拒。PR 编号不作为 Issue。 |
| 关联已有需求和仓库切换 | 不同仓库同号 Issue 各自关联。原连接修订的详情链接被拒。切回原仓库，可重新核对原关联。 |
| 状态独立 | 模拟上游返回已关闭和关闭原因，内部需求、已运行的产品阶段及原交接证据均未改变。 |
| 撤权、限流和网络故障 | 先读取成功，再模拟私有、离线和限流。错误响应不带旧标题或正文。在上游请求未返回时移除项目成员，响应不披露详情。 |
| 带凭据时的公开边界 | 仓库一开始为私有会直接拒绝。仓库在读取期间变为私有时，复核后丢弃详情。 |

以上隔离用例位于 `tests/test_github_issues.py`，涉及阶段证据的用例走真实 Pi SDK 和确定性模型端点。完整看板、跨仓分页、全文搜索、GitHub Projects 分列和私有仓库授权由 #9 的后续切片验收。
