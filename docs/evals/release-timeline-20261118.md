# #16 首版版本计划和时间线验收

真实来源为 [MyAgentDesk GitHub #16](https://github.com/lkun-lea/myagentdesk/issues/16)。浏览器使用隔离项目和测试账号，经 #9 的只读接口关联该 Issue。阶段运行使用官方 Pi SDK 和确定性模型端点。排期、改期、事件、成员权限和来源跳转走实际应用及 PostgreSQL。

| 验收项 | 实际操作与结果 |
| --- | --- |
| 创建、改期和历史 | 创建已承诺版本，将关联 #16 的需求纳入，填目标日期、里程碑及发版必过项。预览延期的原值、新值和影响后，填原因并保存 v2。事件记录能打开原 v1，核对日期、范围、操作人和原因。 |
| 权限和并发 | 浏览器普通成员可读，未显示新建或调整入口。后端先验证普通成员提交被拒，再由两个有权限的账号同时提交同一修订，仅一个成功。移除成员后，时间线及旧修订深链接均返回 404。另一项目的需求不能纳入。 |
| 待排期与范围 | 无目标日期版本保留在待排期。未纳入版本的需求可见。移出需求后当前计数更新，旧范围仍可查。同一需求不能进入两个活动版本，取消原版本后可重新安排。 |
| 阶段和阻塞 | 需求在研发阶段等待本人时，版本计为阻塞。右栏展示负责人与处理期限，可跳需求群、需求证据和 GitHub 原文。决定后沿同一运行完成交接，独立测试通过并由质量负责人确认后才计为阶段已验收。更新项目资料使旧验收失效，计数退回待验收。 |
| 发布时间 | 用过去的目标日期验收，阶段完成后状态仍为等待发布回执，实际发布时间为空。正式发布及回滚依赖 #11 的匹配渠道回执。 |
| 视图与键盘 | 项目默认全宽。点击阻塞打开桌面右栏，Esc 恢复全宽、焦点归回触发按钮。切换事件后可回版本时间线。在 390px 深色下详情下移，横向滚动限定在时间网格，整页无横向溢出。 |

三个新增集成用例位于 `tests/test_release_plans.py`，TypeScript 与 Vite 构建通过。
