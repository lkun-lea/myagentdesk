# #14 tebb 桌面领取与恢复验收

在隔离工作台和 Windows 验收环境中关联真实 [MyAgentDesk #10](https://github.com/lkun-lea/myagentdesk/issues/10)，固定候选 `c6fbba0e950239555c8ca1ff651ea9077b44d804`。使用真实 GitHub 数据、PostgreSQL、tebb 的 WSL + bubblewrap 终端与 Windows DPAPI。两台设备用同一台 Windows 上独立的配对凭据及桌面交付状态模拟，领取和结果走实际 API。重启通过重新建立桌面服务和终端管理器模拟，故障注入用于丢弃响应与断开工作台连接。 [tebb 配套 PR](https://github.com/lkun-lea/tebb/pull/317)

| 场景 | 实际核验 |
| --- | --- |
| 双设备争抢 | 两个配对实例都获得同一待领取派发 `dc54a47c-9428-463e-aa35-556f7ba2c437`。设备 `fd8b9902` 领取后首次响应丢失，设备 `8ab67a3b` 被阻止。成功设备发出一次真实终端启动，另一台零次。 |
| 启动响应丢失 | 在终端返回前终止原桌面处理。原 tebb 运行 `049fd89a7cf74303bdb68e47f28c6ae8` 完成。新服务从终端磁盘记录找回同一编号并整理退出码和输出，无新增运行。 |
| 断线和回执丢失 | 重启时断开工作台，本机产出待回传记录，工作台完成通知为零。重连时丢弃首次写入成功的响应，再次重启并重放。候选可下载，SHA-256 为 `52aa8990dab1037790ca1fb9edfc11dfe99a413d5b87b213d8c066a54a26b8b4`，工作台只有一条 `executor` 完成通知。 |
| 启动未知 | 同一需求的独立验收派发 `09e62607-5558-4168-8b87-456463f22404` 在意图保存后、出现终端记录前中断。重启后找不到原运行，保持「待核对」并上报独立事件 `executor_review`，完成通知总数仍为一，需求仍在独立验收阶段。 |

定向工作台回归另覆盖一次性配对竞争、错误账号、撤销设备、同设备重复领取和同回执重放。tebb 定向回归覆盖无本机确认不启动、找不到原运行后的状态、未送达回执逐字节重放及损坏索引下找到原终端记录。 [回执摘录](tebb-desktop-delivery-20261119.json)

补充复验使用 `56f86ac7af7a4101621d29dc73fe387bf9901c88` 的 tebb，在同一台 Windows 上启动两个真实本地 API 进程，各自持有独立数据目录和配对凭据。两次本机确认通过认证 `/rpc` 提交，只有胜出目录生成一条终端请求，需求群只有一条完成通知。停止并重启胜出进程后，原运行 `e4bc0b9905b047c386dde0674a2563a3` 仍显示已回传。另用 Edge 核对工作台生成配对信息和派发，以及 tebb 的配对、目录确认、原运行和等待补传界面。tebb 浏览器验收使用模拟 RPC，覆盖桌面浅色和紧凑深色。

最终 tebb 提交 `136e266430b34773e7859236d3ecc129072fd1f7` 再通过两个真实桌面进程复验。环回代理实际关闭 HTTP 连接，丢弃领取响应并阻断胜出设备的回传。重启该后台后恢复网络，首次入档的响应也被丢弃。派发 `9321f08c-beef-474c-a201-c70350120483` 发送两次同一回执，共一条完成通知和一次终端启动，运行 `41d3d00cbfd0403d83cf9cfdfaffa071` 保持一致。冷启动、恢复和原日程定时器回归共五项通过。

真实场景使用桌面后台的相同恢复逻辑和实际沙箱。两台物理电脑、安装包的原生 WebView 和文件分片补传留待后续验收。
